# M9a Logs, Gateway and Approvals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Logs screen (Logs, Gateway, Approvals tabs), the Logs badge, the palette action for errors, and gateway alerts.

**Architecture:** Two read-only collector queries (`logs_list`, `logs_read`) plus gateway details and an error count added to the existing `agents` event; two small main services (`GatewayService` for restart and stop, `ApprovalsService` for the read-only commands) and a `GatewayWatcher` for notifications; renderer libs, stores, IO and the screen follow the Sessions and Usage patterns.

**Tech Stack:** Python 3 stdlib (collector, pytest), TypeScript, zod, Electron IPC and `Notification`, React 19, zustand, TanStack Virtual, Vitest, Playwright for Electron.

**Spec:** `docs/superpowers/specs/2026-10-14-m9a-logs-design.md`

## Global Constraints

- UI strings are English only; replies to the user are Indonesian.
- Collector stays stdlib-only and **ASCII-only**; log files are opened read-only from a fixed name list inside the profile's `logs` folder (real path must stay inside it).
- The renderer and main send data only (profile, file name from a fixed enum, offsets, action name); commands are built in main with individually quoted arguments.
- Write files containing backslashes with the Write/Edit tools; for multi-file edits write a Python script file and run it.
- Run Vitest and Playwright one after the other, never at the same time.
- Each task ends with a commit whose message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
