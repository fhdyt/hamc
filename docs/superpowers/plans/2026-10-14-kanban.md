# Kanban Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only Kanban screen over the real `kanban.db` schema, and the agent graph fixed for text task ids.

**Architecture:** Three read-only collector queries over the existing `--query` channel (boards, tasks of a board, one task with its parts); renderer libs, store, IO and screen follow the Sessions pattern. No write, no CLI.

**Tech Stack:** Python 3 stdlib (collector, pytest), TypeScript, zod, React 19, zustand, Vitest, Playwright for Electron.

**Spec:** `docs/superpowers/specs/2026-10-14-kanban-design.md`

## Global Constraints

- UI strings are English only; replies to the user are Indonesian.
- Collector stays stdlib-only and ASCII-only; every database is opened with `open_ro`; the board slug is checked by regex and only mapped to a known database path.
- Write files containing backslashes with the Write/Edit tools; for multi-file edits write a Python script file and run it.
- Run Vitest and Playwright one after the other, never at the same time.
- Each task ends with a commit whose message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

6. **Store and IO.** `stores/kanban.ts`, `kanbanActions.ts`; tests.
7. **Screen.** `screens/Kanban.tsx`, `screens/kanban/Board.tsx`, route, palette hint, styles; e2e first part.
